# 编写中文 LaTeX 数学教材

按用户指定用途编写或修订中文数学学习材料。需要连续自学的教材应让目标读者顺畅学习，不能退化成专家复习提纲；辅助阅读材料按约定范围补足，不默认替代全部来源。在修订时，若要求的是教学修订，应以降低理解障碍为目标，不据此擅自扩大课程范围；数学正确性保持为硬约束。

本技能的数学审校、LaTeX 修复和 PDF 交付检查均以中文数学学习材料为对象。任务不涉及此类材料时，普通 LaTeX 排版、一般 PDF 操作、研究论文或其他用途稿件的审校与交付检查不单独触发本技能。

## 开始前

1. 完整读取用户给出的写作规范、已有模板和项目约定；用户规范优先于本技能的默认值。
2. 对复杂或长周期项目建立持久计划、发现记录和进度日志。先盘点实际编译输入、来源文件、已有改动与输出路径，不覆盖用户未授权修改的原稿。
3. 依任务读取下列参考文件；被选中的文件必须读完：
   - 所有教材任务：读 [教学写作规范](references/pedagogy-and-style.md) 与 [数学严谨性和证明责任](references/mathematical-rigor.md)。
   - 根据资料重制、翻译或整合：再读 [来源重制与覆盖](references/source-reconstruction.md)。
   - 含习题、验收或题解：再读 [习题、题解与超链接](references/exercises-and-links.md)。
   - 创建或重构 LaTeX 工程：再读 [LaTeX 工程规范](references/latex-engineering.md)。
   - 审校、修复或交付：再读 [全文审计与 PDF 终验](references/audit-and-qa.md)。
4. 可复制 [中文数学教材模板](assets/book-template/main.tex) 所在目录作为起点；若项目已有体例，优先沿用并只补缺失能力。
5. 编写或修订时，长任务恢复或上下文压缩后，在继续改稿前，需全文重读当前项目指定的核心教学与证明规范（包括校准示例），项目未指定统一规范时，全文读本技能的教学与证明两份参考文件。其他详细参考按本次任务触发读取，不要求加载全部历史资料。

## 确立写作合同

在动笔前明确并记录：

- 目标读者已经掌握什么，哪些前置必须补入，哪些只需提供调用接口；
- 成品是辅助阅读、可替代单一来源的重制版，还是整合多源的唯一阅读载体；
- 哪些结果必须完整证明，哪些给模型证明，哪些只陈述和使用，须标明星号、阅读要求及未证明边界；
- 内容覆盖边界、预期篇幅、模块结构、交付文件和构建工具；
- 来源的正式书目信息、主要来源与补充来源的身份，以及每个本地代号的唯一映射。

不要用含混的“完整”“自洽”代替边界说明。对象、精确陈述、使用方法和必要依赖在书内可理解；书外结果按[证明参考](references/mathematical-rigor.md)明确标识，不默认展开全部证明。

## 建立工程与覆盖矩阵

1. 长材料使用模块化工程、来源覆盖记录和依赖记录；小型材料沿用适当的现有结构，不为局部任务强建一套全书工程。
2. 建立来源覆盖矩阵，逐项追踪主要概念、命名定理、关键证明机制、正文依赖的例子与习题；不强求逐页或逐题映射。
3. 建立依赖图。首次使用前定义概念；若提前出现只是研究地图预览，明确标为预览并链接到前置接口或正式展开处。
4. 将必备但放正文过长的最低前置放入第零章；把第一遍不需阅读的偏门或技术材料放入附录。正文在首次调用处链接过去。
5. 为长项目按章或按模块分批编写、构建和验收；不要等全书完成后才发现共同记号或证明责任错误。

## 编写与修订

1. 按“动机—定义—例子—定理—证明—结构注记—练习”的学习顺序组织内容。
2. 把正文中首次引入的术语、构造和记号等也视为定义。这些首次依赖均按[教学规范第4.1节](references/pedagogy-and-style.md#definition-basics)检查。
3. 对非平凡证明按具体数学动作编号步骤，一个编号内不得塞入多个动作或大段堆积；长证明、双向或多情形证明再设统一粗体阶段。标题和字号按证明参考第2节，不一定给每步都加标题。逐步补足量词、隐含条件、关键计算或推理、记号与边界情形等关键理由。
4. 非平凡陈述先解释含义；证明引导与证明后注记各按[证明参考第3节](references/mathematical-rigor.md#proof-explanations)承担其作用，不用“显然、标准、容易验证”掩盖实质理由。
5. 未展开证明的非平凡结果加星号，解释含义、用途、阅读与证明边界，并给实际调用的精确版本和来源。
6. 精选习题。正文依赖的习题结论提升为正文；保留题应承担概念检验、关键方法或跨章综合功能。
7. 复用已有文字时采用“大片复制、统一改造、定点补写”，但把机器稿和旧稿只当作待核查来源；逐项复核定义、假设、公式、证明和解释。

## 质量门

交付前必须同时通过7层检查：

1. **数学层：** 人工连续阅读实际编译输入，核查事实、概念、定义、定理、证明、例子、解释、题解和来源归属。

2. **依赖层：** 核查首次定义、前置路由、阅读层级、内部链接、全书约定、量词/符号/术语等。

3. **教学层：** 检查是否有容易使得读者卡壳、疑惑、感到阅读与理解障碍或觉得不自然/缺乏动机/缺乏直觉之处，前置、例子、路线、注记等是否均有实质性作用，新对象、条件、公式是否可理解，步骤为何推进，**新增文字是否降低总负担**，是否有任何其他会对读者的首次学习造成阻碍或困难之处等。

4. **格式层：** 证明是否已按符合要求的格式写作，结构、思路、逻辑是否清晰顺畅，是否有不合要求的大段堆积、过度概括、技术细节淹没正文或缺失等问题，不同字号分工是否正确等。

5. **语言层：** 语言行文是否符合人类阅读习惯、人类学术写作与遣词造句的惯例，是否过度工程化/代码化或使用人类不常用的语句组织方法等；是否有祈使句指导语气不完整、断句不自然、突兀停句、成分残缺、必要的虚词/过渡词/辅助词过度省略、相邻句连接不顺、上下文不连贯、过度不顺畅、突兀转向等，是否有过度防御性措辞、过度提醒、反复否决、虚空打靶等，是否有其他任何影响文法质量和人类阅读体验的问题等。

6. **工程层：** 构建至引用稳定，检查未定义引用、重复标签、缺失文献、书签、缺字、盒溢出、占位符和弃用术语。可运行：

   `python scripts/audit_latex_project.py path/to/main.tex --terms path/to/terms.json --log path/to/main.log`

7. **视觉层：** 全页渲染 PDF；用接触表覆盖全书，并以原尺寸检查章首页、长证明、复杂公式、表格、题目、题解和本轮高风险修改页。

静态脚本只作辅助，不能替代逐章数学阅读；声称需与实际工作完成的内容一致，不得以编译通过充当任务完成；外部审计报告只作为待验证主张，逐条给出采纳、部分采纳或不采纳的数学理由。

- 当用户指出不足之处，举例说明并要求修改时，需要根据语境判断清楚用户是希望定点修改，还是指出某个一般性问题希望全量修改而具体例子仅作为示例。若用户是举例而非要求定点修改，**应当主动检查其他地方的类似问题，不得只重点修改点名位置而对其他地方的类似问题草率对待甚至视若罔闻，不将用户抽读到的范围视为全部合格。**
- 当任务为定点修改时，不因小范围定点修改就重读全书或做重复全量一般审计。

## 交付

报告本轮实际产生的源码、核验稿、检查结果和保留边界；发布位置及覆盖权限按用户约定。保护原稿和回退点，发布文件应与最后核验的构建文件一致；不能把“核验候选”擅自改称已批准的正式发布稿。

可声称“在本轮明确范围内未再发现错误”，但不得用免责声明掩盖实际工作责任。
